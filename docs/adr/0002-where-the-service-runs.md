# 0002. Where the service runs / Къде работи услугата

**Status / Статус:** Accepted

## Context / Контекст

Досега приложението се пуска само локално с `uvicorn app.main:app --reload`. Трябва да решим къде ще работи услугата в следващите упражнения, така че да е еднаква за всички и лесна за автоматизиране.

## Options / Варианти

1. **Собствени Linux сървъри (`infra/servers`: web1, web2, db, lb)**
   - Вече са подготвени в хранилището; пускат се с `docker compose`.
   - Два web сървъра зад load balancer: можем да упражним разпределяне на натоварването.
   - Безплатно, работи локално и в Codespaces.
   - Трябва сами да ги настройваме (Ansible) и поддържаме.
2. **Облачна платформа (PaaS, напр. Render, Azure App Service)**
   - Без грижа за сървъри; публичен адрес веднага.
   - Нужни са акаунт и често карта; лимити в безплатния план.
   - Скрива точно онова, което курсът трябва да ни научи.
3. **Само локално на всеки лаптоп**
   - Нищо за настройване.
   - Различно е при всеки; няма общ адрес; не е реално внедряване.

## Decision / Решение

Услугата работи на сървърите `web1` и `web2` от `infra/servers`, зад load balancer `lb` (порт 8080 → 80). Базата е на сървъра `db`.

## Consequences / Последствия

- Средата е еднаква за всички и се пуска с една команда.
- Трябва да автоматизираме настройката на сървърите (Ansible).
- С два web сървъра можем да обновяваме без прекъсване на услугата.
